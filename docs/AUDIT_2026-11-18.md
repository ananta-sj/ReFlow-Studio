# ReFlow audit — November 18, 2026

What this repo does: ReFlow coordinates local and optional remote media/AI tools for transcription, editing, translation, speech, review and export. Its founding goal includes family-friendly viewing and selective dialogue changes. Load assumed: one desktop user with long episode jobs, worker subprocesses and persistent recovery files, not a public multi-tenant web service.

Baseline: main, 7bf37cc9b705f8c98286f90f92926491a62d0419. This report records the read-only audit before the separate owner-authorized fix phase. Status of any later fixes belongs in the verification notes below.

## Must fix

1. **Cloud translation fails before it contacts the service** (`core/providers/cloud_rest_common.py:54-70`; `core/providers/translation/cloud_rest.py:37,94`).
   - **What this is:** The shared helper builds connection/read timeout values for every cloud adapter.
   - **Problem:** Both translation presets pass `(5,120)`. The helper evaluates `min(15,(5,120))`, which raises TypeError before the HTTP call. The selected translation route cannot run.
   - **Fix:** Preserve an explicitly supplied timeout pair; expand only scalar timeouts. Add a regression at the actual shared-helper boundary.
   - **If we skip it:** The cloud/local-service translation option fails regardless of model quality.

2. **Failed service calls can expose secrets in logs** (`core/providers/cloud_rest_common.py:81-86,118-120`).
   - **What this is:** The helper turns network and remote-job failures into user-visible exceptions.
   - **Problem:** A signed URL such as `https://service.test/file?token=fixture-private` and an upstream exception/payload are interpolated verbatim. Those messages can become persisted diagnostics or user-shared logs; chained exceptions can print the original data too.
   - **Fix:** Emit bounded generic operation/status messages and suppress unsafe exception context. Do not echo full URLs, headers or arbitrary remote payloads.
   - **If we skip it:** Sharing an ordinary failure report can disclose service tokens or private remote data.

3. **Custom profanity requests can ignore the requested policy silently** (`core/providers/profanity_filter/cloud_rest.py:38-53`).
   - **What this is:** A configured service rewrites dialogue according to optional user instructions.
   - **Problem:** With a default body containing only `{text}`, nonempty `custom_instructions` never reaches the provider. Formatting/truncation can discard it too while the UI appears configured. Translation had a related check that could be fooled when source text in the same field matched the intended policy.
   - **Fix:** Require an explicit unmodified instructions placeholder when instructions are set, or fail before contacting the service. Preserve the no-instructions path.
   - **If we skip it:** A user-specified censorship policy can be ignored without a useful error.

## Should fix

4. **Unauthenticated compatible speech services receive a fake authorization token** (`core/providers/tts/cloud_rest.py:16-24`).
   - **What this is:** The OpenAI-compatible preset is usable with self-hosted local services where no credential is configured.
   - **Problem:** Unlike translation, the TTS and corresponding compatible STT paths send `Authorization: Bearer None`. A service that accepts anonymous requests but rejects invalid supplied credentials fails unnecessarily.
   - **Fix:** Omit the header when no key exists. Keep the exact header when a real key is configured.
   - **If we skip it:** Some otherwise compatible local speech services fail for an artificial authentication error.

5. **A build-tool dependency has a known expensive-pattern vulnerability** (`frontend/package-lock.json:4076-4078,4372-4380`).
   - **What this is:** picomatch matches filename patterns in the Vite toolchain; npm reports five packages because the advisory propagates through parents.
   - **Problem:** GHSA-fc5q-39xc-vjpf describes exponential matching time for crafted repeated-extglob patterns. The audited version is 4.0.7. The official advisory lists no patched version at review time.
   - **Fix:** Keep untrusted glob patterns out of build configuration; review upstream remediation rather than force-downgrading Vite/React tooling. Recheck by December 2, 2026, or before the next release, whichever occurs first.
   - **If we skip it:** A future feature that feeds attacker-controlled globs into this chain can freeze a build/server. No such runtime UI surface was found in this audit; this is not demonstrated remote code execution in the desktop app.

Official advisory: https://github.com/advisories/GHSA-fc5q-39xc-vjpf

## Nice to have

6. **The shared HTTP module description is not a Python docstring** (`core/providers/cloud_rest_common.py:1-18`).
   - **What this is:** A central helper used by multiple providers.
   - **Problem:** An import precedes the intended module docstring, so Python does not recognize that description as the module documentation.
   - **Fix:** Move the existing local import below the docstring while fixing this same file. Do not refactor unrelated providers.
   - **If we skip it:** No user-visible failure; the file stays a little harder to maintain.

Verdict: repair the shared HTTP contract, log privacy and censorship-policy transmission first; retain the conservative export/recovery safeguards.
Lean: no new runtime dependencies; no unsupported line-count or whole-project dependency-removal claim.
Not checked: actual AI inference or episode quality; GUI runtime; compiled/vendor AI internals; full backend integration with absent third-party packages; native Linux/Mac execution; exhaustive skill-plugin source scanning; unpublished credentials/private archives. Archive/deletion/queue/bridge boundaries were traced selectively; no blanket absence-of-vulnerabilities claim is warranted.

## Existing-app startup recovery — November 18, 2026

A later owner-approved repair addresses startup transport failures. The interface
now renders its startup screen before saved preferences are loaded, offers retry
if those settings cannot be read, and bounds waiting for the desktop bridge.
Integrity-check rejection or a stalled check exposes recovery instead of leaving
the boot overlay indefinitely. Ordinary integrity results reporting missing
engines still allow the existing diagnostic interface to open. Late startup
responses are ignored after timeout or effect cleanup. Normal render requests
receive no new execution deadline.

Run `npm run test:startup` in frontend: nine dependency-free-of-new-packages
regressions exercise actual transpiled modules with simulated bridge/timers/hooks,
plus server-rendered retry markup. They cover missing/delayed bridge, cleanup and
retry, rejected preferences, late response preservation, bootstrap ordering,
integrity transport failure versus returned ok:false, and long render calls.
The native-build workflow runs them after its existing npm ci step.

Production build passes; lint retains 24 existing warnings and no errors; the
21 cloud boundary regressions still pass. Independent source review found no
blocking issue in this slice. Native GUI launch, real StrictMode interaction,
model inference and whole-episode quality were not verified by these tests.

model, service account, commit or push was added.
