# Runtime dependency and device checks — 9 October 2026

## Result and authorization

This increment extends the selected-setup inspection with an explicit dependency/device smoke check for the currently supported pinned Whisper Turbo, IndicTrans2 and IndicF5 routes. The user authorized continued development without live model calls. No model/package/framework/tool installation, download, API request, model weight loading, translation, speech generation or video render was performed. Actual checks use existing interpreters and a tiny tensor calculation.

Other engines remain explicitly unverified where no bounded runtime contract is implemented. This is partial A07 work, not a claim of universal engine support or release readiness.

## Application controls and job ownership

The Dashboard retains the file-only **Check selected setup** action and adds **Check runtime dependencies and device**. Runtime checks are opt-in; the file-only action cannot launch them. The UI explains import/device checks, the 45-second recognition/translation and 90-second Hindi-speech process timeouts and absence of model loading. Reports display runtime outcomes, selected GPU name when measured, and setup guidance for actual failures. Changed parameters discard stale responses as before.

The bridge freezes the registry and reuses the execution template/cast mapping. Under the existing render lock it reserves a runtime-check flag, rejects checks during active jobs/downloads/another check, then releases the lock while processes execute. New render/review work and deletion/reset operations that use the shared busy/start guards are rejected during the check. The reservation clears in a finally block even on invalid parameters or an inspection exception. This does not freeze arbitrary settings/registry edits; the returned snapshot is a point-in-time preview, and execution still revalidates its accepted configuration.

## Probe contract and isolation

`core/runtime_probe.py` launches only the fixed `core/runtime_probe_worker.py` entry point through the existing owned subprocess machinery and selected interpreter. Supported pairs are Whisper Turbo/CUDA 0, IndicTrans2/CUDA 0 and IndicF5/CPU or CUDA 0. Unsupported adapter/device pairs fail before starting a process. A semaphore prevents overlapping direct probes; a second caller receives an unverified/retry-later result.

Each probe creates a fresh RenderContext workspace. Temporary/cache environment paths, including Matplotlib's configuration/font cache, point into that workspace, bytecode writing is disabled, and Hugging Face/Transformers/global offline flags are enabled. The worker also rejects Python socket connection audit events, guarding against unexpected import-time connection attempts. Existing runtime directories, profile metadata, credentials and model files are not modified. The process is hidden on Windows, uses file-backed diagnostics and has a 45-second recognition/translation or 90-second Hindi-speech timeout; termination and workspace cleanup can add time beyond those limits. Process ownership/cleanup are retained through existing RenderContext mechanisms.

Reports are limited to 64 KiB and bound to schema, adapter and device. Passed/failed status must agree with the problems list, versions must be strings, and `model_loaded` must remain false. Missing, oversized, malformed or contradictory reports fail closed. Raw import diagnostics are not returned to the interface; temporary diagnostics are removed with the owned workspace. The worker records a bounded progress phase so a timeout identifies the incomplete step. Timeout means **unverified**, not evidence that an installation is broken.

## What is checked

All supported routes check pinned PyTorch versions, the approved package origin and tiny 2-by-2 matrix arithmetic on the selected device. CUDA routes check availability, synchronize the operation and record the first GPU's name. CPU IndicF5 requires the existing CPU build. No model class is instantiated and no checkpoint/tokenizer/vocoder state is loaded.

Whisper Turbo checks its existing Transformers 5.18.0 and importable AutoProcessor, AutoModelForSpeechSeq2Seq and stopping-criteria symbols. IndicTrans2 checks Transformers 4.51.3 and corresponding tokenizer/sequence-to-sequence symbols. IndicF5 checks f5-tts 0.1.0 plus imports of torchaudio, soundfile, safetensors, Vocos and its F5 model/inference utilities. Importing symbols verifies dependency compatibility only; it does not verify a real model load or synthesis call.

Device routing follows the selected engine profile rather than treating the Dashboard choice as authoritative. Whisper Turbo and IndicTrans2 use CUDA 0; IndicF5 uses its configured speech device. IndicTrans2 intentionally imports CUDA PyTorch from the existing IndicF5 GPU profile through its configured shared dependency layout. The checker accepts that specific sharing arrangement instead of requiring packages beneath IndicTrans2's interpreter directory. Other unexpected PyTorch origins fail.
