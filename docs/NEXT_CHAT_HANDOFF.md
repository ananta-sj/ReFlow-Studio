# Desktop testing overview

The next development stage focuses on testing the existing desktop application before expanding the dubbing pipeline. Follow the [public roadmap](ROADMAP.md) and [contribution guide](../CONTRIBUTING.md).

1. Locate and reproduce existing issues.
2. Test real application interactions and recovery behaviour.
3. Make focused fixes and repeat the affected tests.
4. Review security and regressions before publishing changes.
5. Continue with pipeline reliability, dubbing quality and multi-character workflows.

Preserve user data and use permitted test material. Record observed results and limitations; a successful build alone does not establish native usability or dubbing quality.

Maintainers keep detailed session handoffs, local environment information and private evidence outside the public source distribution. Obtain relevant context from the maintainer before resuming an investigation. Report vulnerabilities privately through the [security policy](../.github/SECURITY.md).
